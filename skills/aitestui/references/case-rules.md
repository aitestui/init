# 用例规则与静态校验

## 平台现行真相（勿凭记忆）

- 平台只执行**自然语言（prompt）用例**：库里只存 `promptContent`，`format` / `script_content` / `self_heal_enabled` 等字段仅供往返存档、执行链不读，不存在 YAML 用例与用例级自愈（ADR-0063）。
- 用例导入导出端点**现行有效**：`POST /test-cases/import` 收纯 JSON 7 列用例（ADR-0033；曾被 ADR-0063 下线，已由 ADR-0070 整体回退恢复）。详见 `references/api-contract.md`。
- 若发现平台源码或文档与本段冲突，以本段与 `docs/adr/0075` 为准。

## 10 条硬约束（aitestui 用户手册 §6.2）

生成与每次修改用例后，逐条核对：

1. 全文中文、纯自然语言，一条用例一段；不输出 YAML/JSON/代码/表格。
2. 首行是标题，≤20 字，平台派生为用例名。
3. 步骤编号、动词开头（`打开 / 输入 / 点击 / 选择 / 记录`），每步一个动作。
4. 元素按用户可见文案描述，禁坐标/CSS/XPath/「第 3 个按钮」。
5. 可变数据用 `${VAR}` 占位（账号/金额/商品名/地址）。
6. 已配 COOKIE 免登录就不写登录步骤。
7. 入口只写 `/path`，全文不许出现 `http://` / `https://`。
8. 以「断言：」结尾，且是能在当前页直接判定真假的存在性陈述。
9. 断言不写会变的具体数值（金额/耗时/订单号/时间戳/条数）；这类值另起「记录：」步骤。
10. 不写平台判定不了的步骤（「检查控制台报错」「等待 5 秒」「验证接口返回」）。

## 分层标签

- `冒烟`：主链路最小集，一次登录后的核心可见性验证，失败即阻断下一批。
- `核心`：覆盖主要业务功能，冒烟是其子集。
- `负向`：错误输入、越权、边界，断言「系统正确拒绝/提示」。全量 = 核心 ∪ 负向。

## 静态校验脚本

`scripts/case-lint.mjs <pool.json>`：读入 7 列 JSON 数组，逐条检查 title 长度、必须以「断言：」结尾、无 `http(s)://`、format=prompt、code 合规、tags 合法。输出不合规项，退出码非 0 表示需自修。

```bash
node scripts/case-lint.mjs output/<run>/pool.json
```
