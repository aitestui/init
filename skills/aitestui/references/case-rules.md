# 用例规则与静态校验

## 平台现行真相（勿凭记忆）

- 平台只执行**自然语言（prompt）用例**：库里只存 `promptContent`，`format` / `script_content` / `self_heal_enabled` 等字段仅供往返存档、执行链不读，不存在 YAML 用例与用例级自愈。
- 用例导入导出端点**现行有效**：`POST /test-cases/import` 收纯 JSON 7 列用例。详见 `references/api-contract.md`。
- 若发现平台源码或文档与本段冲突，以本段为准。

## 10 条硬约束（aitestui 用户手册 §6.2）

生成与每次修改用例后，逐条核对：

1. 全文中文、纯自然语言，一条用例一段；不输出 YAML/JSON/代码/表格。
2. 首行是标题，≤20 字，平台派生为用例名。
3. 步骤编号、动词开头（`打开 / 输入 / 点击 / 选择 / 记录`），每步一个动作。
4. 元素按用户可见文案描述，禁坐标/CSS/XPath/「第 3 个按钮」。
5. 可变数据用 `${VAR}` 占位（账号/金额/商品名/地址）。
6. 已配 COOKIE 免登录就不写登录步骤。
7. **入口按项目类型写**：web 项目只写 `/path`、全文不许出现 `http://`/`https://`；**桌面应用项目（windows/computer）无 URL，入口写被测应用的可启动标识**——应用名（如 `打开「XX 客户端」`）或可执行文件路径（如 `打开 C:\Program Files\XX\XX.exe`），由 runner 桌面会话启动，同样不写 `http(s)://`、不写 `/path`。安卓项目入口写应用名/包名。
8. 以「断言：」结尾，且是能在当前页直接判定真假的存在性陈述。
9. 断言不写会变的具体数值（金额/耗时/订单号/时间戳/条数）；这类值另起「记录：」步骤。
10. 不写平台判定不了的步骤（「检查控制台报错」「等待 5 秒」「验证接口返回」）。

## 分层标签

`tags` 在 `pool.json` 里是**字符串数组**（如 `["冒烟","核心"]`），不是逗号分隔的字符串。

- `冒烟`：主链路最小集，一次登录后的核心可见性验证，失败即阻断下一批。
- `核心`：覆盖主要业务功能，冒烟是其子集。
- `负向`：错误输入、越权、边界，断言「系统正确拒绝/提示」。全量 = 核心 ∪ 负向。

XLSX 往返模板的 `tags` 单元格是 `"冒烟,核心"` 文本、由平台前端切分；本 skill 直接 POST 的 JSON 没有这一步，必须自己给数组。单个标签 ≤ 64 字、每条用例 ≤ 20 个标签。

## 静态校验脚本

`scripts/case-lint.mjs <pool.json>`：读入 7 列 JSON 数组，逐条检查标题长度与「断言：」结尾、无 `http(s)://`、format=prompt、code 合规、tags **必须是字符串数组**且标签合法、`selfHealEnabled` 为数字 `0|1`、各文本字段类型与长度。输出不合规项，退出码非 0 表示需自修。**类型检查刻意不做隐式转换**——校验通过但导入被 422 拒绝更难排查。

```bash
node scripts/case-lint.mjs output/<run>/pool.json
```
